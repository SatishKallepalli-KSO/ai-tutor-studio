Technical design

System architecture

Dual-audience talent studio: React client, FastAPI (v0.6), identity + social + jobs store, Stripe, optional OpenAI — plus static GitHub Pages demos with local fallbacks.

High-level topology

flowchart LR L[Learner] --> W[Web React + Vite] R[Recruiter] --> W W -->|JWT + REST| A[FastAPI API] A --> DB[(Postgres or SQLite)] A --> S[Stripe] A --> O[OpenAI optional] W -.->|Pages demo| LOC[Local rubric + localStorage] S --> A DB --- U[Users personas] DB --- P[Profiles] DB --- J[Jobs] DB --- C[Connections] DB --- M[Messages] DB --- E[Feature events]

Logical components

apps/web

Learn/Practice · Jobs · Profile · Network · Chat · Paths · Pricing · Admin. Persona switcher (learner / recruiter). Lean primary nav + More menu.

apps/api

Auth + persona · entitlements · Stripe · tutor feedback · jobs · profiles · connections · messages · admin analytics · public stats.

Curriculum

curriculum.ts topic docs · question banks · agenticPath.ts / snowflakePath.ts video curricula.

docs/ + docs/product/

Entitlements

  • Learn: all tracks + video paths always readable.
  • Free practice: html, css, javascript, python, java-to-python · 5 feedbacks / UTC day.
  • Pro: all tracks · unlimited feedback · Stripe portal.
  • Social + jobs: available on Free and Pro (persist with API; localStorage fallback on Pages).
  • Admin: ADMIN_EMAILS → /admin.

UI architecture (current)

  • Editorial dark theme: Fraunces + Sora · jade + champagne accents.
  • Primary nav: Learn · Jobs · Network · Chat (+ More).
  • Compact page heads: title + one-line sub + single CTA.
  • Pages-only mode: demo jobs, profiles, connections, chat in browser.

Security talking points

  • bcrypt passwords · JWT bearer · Stripe secrets server-side only.
  • Feedback, checkout, messaging, and job posts require auth where gated.
  • Private profiles hidden from public talent browse.
  • Chat only between accepted connections.
  • Voice stays in-browser (Web Speech API) by default.
