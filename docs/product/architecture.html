Technical design

System architecture

A production-shaped freemium tutoring stack: React client, FastAPI backend, SQLite/Postgres identity & usage store, Stripe billing, and optional OpenAI coaching — with a static GitHub Pages mode for demos.

High-level topology

flowchart LR U[Learner / Buyer] --> W[Web app React + Vite] W -->|JWT + REST| A[FastAPI API] A --> DB[(Users / usage SQLite or Postgres)] A --> S[Stripe Checkout Portal Webhooks] A --> O[OpenAI optional] W -.->|static Pages demo| L[Local rubric + browser speech] S --> A

Logical components

apps/web

Tracks, Learn docs, Practice (text/voice), Pricing, Auth UI. SpeechRecognition for dictation; SpeechSynthesis for “Hear question”.

apps/api

Auth (register/login/JWT), entitlements, Stripe, tutor feedback, optional static SPA hosting from Docker.

Curriculum layer

curriculum.ts topic docs + data.ts / content.json questions linked by topic_id.

docs/ + docs/product/

GitHub Pages ships the app build; docs/product/ holds this sellable documentation site (preserved on publish).

  stripe_customer_id, stripe_subscription_id
  subscription_status: inactive | active | trialing | demo | canceled…

UsageCounter
  user_id, day, feedback_count

Entitlements

  • Learn: all tracks always readable (acquisition funnel).
  • Free practice tracks: html, css, javascript, python.
  • Free feedback: 5 / UTC day.
  • Pro: all tracks + unlimited feedback; Stripe portal.
  • Demo upgrade: local Pro unlock when Stripe is not configured.

Security posture (sales-ready talking points)

  • Passwords hashed with bcrypt; JWT bearer tokens.
  • Stripe secrets only on server; webhook signature support.
  • Feedback and checkout require authenticated sessions.
  • CORS configurable; production should set strong JWT_SECRET.
  • Voice stays in-browser (Web Speech API) — audio is not uploaded by default.
