Go-live runbook

Launch the talent studio (Learn · Practice · Hire) with live AI coaching and Stripe. Checklist from empty hosting to first paid Pro user — plus persistent jobs, profiles, and chat.

Markdown source Free / Pro matrix Architecture

1. What you deploy

Piece Role Production
API (apps/api) Auth, personas, plans, Stripe, AI feedback, jobs, profiles, connections, chat, admin Required
Web (apps/web) Learn/Practice, Jobs, Profile, Network, Chat, paths, pricing, admin Required (bundled in Docker)
Postgres Users, social, jobs, usage, feature events Strongly recommended
OpenAI Rich coaching (rubric fallback without key) Recommended
Stripe Checkout, portal, webhooks → Pro Required to monetize

Product: Learn. Practice. Hire. Recommended shape: one Docker service (API serves the built UI) + managed Postgres + Stripe + OpenAI. Repo includes Dockerfile, render.yaml, and .env.example.

2. Pre-flight

  • Public HTTPS URL decided (e.g. https://app.yourdomain.com)
  • OpenAI account with billing + API key
  • Stripe account (test mode first, then live)
  • Admin emails for ADMIN_EMAILS
  • Strong random JWT_SECRET (32+ chars)
  • Postgres ready (avoid SQLite for real traffic)
  • ALLOW_DEMO_UPGRADE=false in production
python3 -c "import secrets; print(secrets.token_urlsafe(48))"

3. Environment variables

Variable Required Notes
JWT_SECRET Yes Long random string
APP_URL Yes Public UI origin for Stripe redirects
DATABASE_URL Recommended postgresql://user:pass@host:5432/db
OPENAI_API_KEY Recommended Enables model coaching
OPENAI_TUTOR_MODEL No Default gpt-4o-mini
STRIPE_SECRET_KEY For pay sk_test_… then sk_live_…
STRIPE_PRICE_MONTHLY For pay Pro monthly Price ID
STRIPE_PRICE_YEARLY Recommended Pro yearly Price ID
STRIPE_WEBHOOK_SECRET For pay From Stripe webhook endpoint
ALLOW_DEMO_UPGRADE Must be false live Local-only Pro unlock when Stripe off
ADMIN_EMAILS Recommended Comma-separated → /admin access

If UI is hosted separately (e.g. GitHub Pages), build with VITE_API_BASE=https://YOUR-API and matching VITE_BASE. Docker default serves UI from the same host with VITE_BASE=/.

4. Integrate AI (OpenAI)

Setup Create API key

platform.openai.com → API keys. Add billing. Set OPENAI_API_KEY. Keep model on gpt-4o-mini to start.

Behavior With / without key

With key: richer coaching on POST /v1/tutor/feedback. Without key: rubric fallback still works for demos.

Smoke test

curl -s https://YOUR_HOST/healthz

# After register/login, POST feedback with Bearer JWT.
# Confirm response "provider" reflects OpenAI when configured.

Free plan already caps 5 feedbacks/day — watch OpenAI usage the first week once Pro unlimited is live.

5. Integrate payments (Stripe)

  1. Products → add AI Tutor Studio Pro with monthly ($19) and yearly ($149) prices. Copy Price IDs into env.
  2. Developers → API keys → set STRIPE_SECRET_KEY.
  3. Webhooks → endpoint https://YOUR_HOST/v1/billing/webhook
    Events: checkout.session.completed, customer.subscription.updated, customer.subscription.deleted.
    Copy signing secret → STRIPE_WEBHOOK_SECRET.
  4. Enable Customer Portal (cancel / update payment). App uses POST /v1/billing/portal.
  5. Set APP_URL so success/cancel/portal redirects land on your UI.

Payment smoke test (test mode)

  1. Register → /pricing → Upgrade → Checkout
  2. Card 4242 4242 4242 4242
  3. Confirm webhook delivered in Stripe
  4. App shows Pro; Staff/EM unlock; unlimited feedback
  5. Portal cancel → Free after webhook

Then switch Stripe to Live, create live prices, replace env keys + webhook secret, redeploy with ALLOW_DEMO_UPGRADE=false.

6. Deploy on any cloud

Option A — Render (fastest)

  1. Push repo → Render → New → Blueprint (render.yaml)
  2. Attach Postgres; set DATABASE_URL
  3. Fill env from §3
  4. Health check path: /healthz
  5. Custom domain → update APP_URL + Stripe webhook URL

Option B — Railway / Fly / Cloud Run / Azure / AWS

Same Docker image everywhere:

docker build -t ai-tutor-studio .
docker run --rm -p 8000:8000 \
  -e JWT_SECRET=... \
  -e APP_URL=https://YOUR_HOST \
  -e DATABASE_URL=postgresql://... \
  -e OPENAI_API_KEY=sk-... \
  -e STRIPE_SECRET_KEY=sk_... \
  -e STRIPE_PRICE_MONTHLY=price_... \
  -e STRIPE_PRICE_YEARLY=price_... \
  -e STRIPE_WEBHOOK_SECRET=whsec_... \
  -e ALLOW_DEMO_UPGRADE=false \
  -e ADMIN_EMAILS=you@example.com \
  ai-tutor-studio
  • Cloud Run / App Runner: port 8000; attach managed Postgres
  • Fly.io: Dockerfile + fly secrets set + Fly Postgres
  • Railway: Dockerfile + Postgres plugin + env
  • Azure / K8s: container + managed Postgres + Ingress TLS

Option C — GitHub Pages UI + cloud API

cd apps/web
VITE_BASE=/ai-tutor-studio/ \
VITE_API_BASE=https://YOUR-API-HOST \
npm run build
# publish via ./scripts/publish-pages.sh (keeps docs/product/)

Prefer one Docker host for a sellable product — simpler Stripe redirects and ops. Pages-only cannot store users or charge cards.

7. Admin dashboard

  1. Set ADMIN_EMAILS=you@example.com on the API
  2. Register or sign in with that email
  3. Open /admin — signups, Free/Pro mix, feature usage

If Admin is missing from the nav, sign out and back in after the env change.

8. Security checklist

  • JWT_SECRET unique and private
  • ALLOW_DEMO_UPGRADE=false
  • Never commit .env; live Stripe keys only on prod
  • HTTPS everywhere; lock down ADMIN_EMAILS
  • Postgres backups / provider snapshots
  • Monitor OpenAI spend + Stripe disputes week one

9. Launch-day verification (30 min)

  1. /healthz → ok
  2. Register → user appears in /admin
  3. Free practice works; Staff locked
  4. Feedback returns AI; Free quota increments
  5. Checkout → webhook → Pro badge
  6. Pro unlocks advanced tracks; unlimited feedback
  7. Billing portal opens
  8. Voice practice shows delivery tips
  9. Agentic path loads; mark-complete works
  10. Admin shows feature events

10. Fastest path to “sell tomorrow”

  1. Deploy Docker to Render with Postgres
  2. Set JWT_SECRET, APP_URL, ADMIN_EMAILS
  3. Add OpenAI key
  4. Stripe test → webhook → prove Pro
  5. Switch Stripe to live
  6. Custom domain → share /pricing

You do not need GitHub Pages for monetization — the Docker image already serves the full product.
